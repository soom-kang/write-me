# 0.3.3 검증

`2026-10-13`에 산문 윤문에서 원문에 없는 인과관계가 생기는 문제를 보완했습니다. 기존 `0.3.2` 실패에서는 Claude Code가 `write-me`를 호출한 뒤에도 “시험 운영 중이며”를 “시험 운영 중이라”로 바꿨습니다. 선택 누락이 아니라 편집 과정의 의미 보존 실패입니다. 모델이 지침을 놓친 내부 이유는 확인하지 못했습니다.

## 보완 범위

- `SKILL.md`: 버전을 `0.3.3`으로 올리고, 작성 전 사실 사이의 관계 확인과 완료 전 연결 표현 대조를 추가했습니다. 읽기 편의 항목에 있던 인과관계 보호 규칙은 의미 확인 단계로 옮겨 보완했습니다.
- `editing-guide.md`: 나열을 인과로 바꾸지 않는 사례와 원래 인과관계를 유지하는 사례를 추가했습니다. 산문 형식이 문장 결합을 요구하는 것은 아니라는 점도 명시했습니다.
- description·호출 조건·자동 선택 policy·mode·parameter는 유지했습니다. 병렬 항목의 불릿 기준, 산문·학술·간결한 원문의 형식 예외, 출력·권한 규칙도 유지했습니다.

특정 연결어를 일괄 금지하거나 실패 문장을 정답으로 넣지 않았습니다. `-이라`를 포함한 연결 표현을 바꿀 때 원문에 해당 관계가 있는지 확인하도록 했습니다. 기존 인과관계도 지워지지 않아야 하므로 별도의 학술 산문 사례를 함께 확인했습니다.

## 실패했던 같은 입력을 각 3회 실행

Codex `0.162.1`과 Claude Code `2.1.296`의 새 세션에서 같은 이름 없는 산문 요청을 각각 3회 실행했습니다. 입력은 앞선 실패 사례와 bytes가 같으며, SHA-256은 `da5b237d3f746753819d894e335bd8798a49d7ec999f2bde942f6253f4e0dd8f`입니다. 사용자 입력에 Skill 이름·경로·인과관계 보존 힌트를 추가하지 않았습니다.

회차마다 빈 임시 작업 디렉터리와 새 세션을 사용했습니다. 기존 CLI 옵션과 기본 모델 설정을 유지하고, 검증 도중 Skill·입력·옵션을 변경하거나 결과를 대체하는 재시도를 하지 않았습니다. 입력과 기준은 실행 전에 기록했으며, 최종 응답을 원문과 대조해 판정했습니다. 실행 중 진행 안내는 최종 출력과 구분했습니다.

Codex 세 회차에서는 설치된 `SKILL.md` 읽기 성공과 `version: "0.3.3"`을 관측했습니다. Claude Code 세 회차에서는 `Skill(write-me)` 호출과 사용자 설치 경로의 본문 확장 event를 관측했습니다. Claude Code의 command 목록에 `write-me`가 있었고 permission denial은 없었습니다. 버전 동일성은 실행 전후 설치 파일의 SHA-256으로도 확인했으며, 사용 선언이나 문체만으로 자동 선택을 판정하지 않았습니다.

## 학술 산문의 기존 인과관계 보호

기존 인과관계를 불필요하게 지우는 부작용을 확인하기 위해 새 학술 산문 입력을 각 CLI에서 한 번씩 실행했습니다. 이 두 건은 위 산문 3회 반복 집계에 포함하지 않습니다. 입력은 실제 연구 결과가 아닌 검증용 예문입니다.

| CLI | 자동 선택 | 학술 산문 유지 | 기존 인과관계·보호 정보 | 전체 |
|---|---|---|---|---|
| Codex | `PASS` | `PASS` | `PASS` | `PASS` |
| Claude Code | `PASS` | `PASS` | `PASS` | `PASS` |

두 출력 모두 장비 오류가 기록 제외의 원인이라는 관계를 유지하고, 제외 기록에 이상치가 포함됐다는 별도 사실을 새로운 제외 사유로 바꾸지 않았습니다. `48건 중 3건`, 날짜, 일반화 불가, 표본 확대에 따른 변화 가능성, 재분석 조건을 보존했습니다. 직접 인용과 코드의 bytes도 같았습니다. 한다체 산문을 유지했고 제목·목록을 추가하지 않았습니다. 자동 선택 근거는 각각 설치 지침 읽기 성공·버전 확인과 `Skill(write-me)`·본문 확장 event입니다.

## 실행 증거와 설치 확인

총 **8 PASS·0 FAIL·0 BLOCKED**이며, 서로 다른 최상위 session ID 여덟 개를 확인했습니다. Codex 학술 실행에서는 `collab_tool_call`도 관측했습니다. 따라서 여덟 건은 최상위 요청 수이며 내부 하위 실행 수를 뜻하지 않습니다.

| CLI·사례 | Session ID |
|---|---|
| Codex 산문 1 | `01a133bc-eab2-7981-8569-4ae4e5c4874a` |
| Codex 산문 2 | `01a133bd-3c26-77b1-98fa-83df508e538e` |
| Codex 산문 3 | `01a133bd-8ad5-7e32-ac31-52dca5c4236e` |
| Codex 학술 | `01a133be-022f-70a0-b2d4-5e1055a77367` |
| Claude Code 산문 1 | `7d13c15e-bde8-4f11-b86d-b83d587ce79b` |
| Claude Code 산문 2 | `0acf602d-de75-48fd-91c9-6b223e59a047` |
| Claude Code 산문 3 | `8544a116-0b17-45bc-b1d7-b5ba1c04e803` |
| Claude Code 학술 | `70246488-352c-4e23-85e6-f258c962f34a` |

실행 명령은 다음과 같습니다. `<empty_cwd>`는 회차별 빈 디렉터리이며 `<prompt_file>`은 위 입력을 담은 UTF-8 파일입니다. 실제 실행에서는 같은 입력 문자열을 subprocess의 stdin으로 전달했습니다. Claude Code도 해당 빈 디렉터리에서 실행했습니다.

```sh
codex --no-daemon exec --ephemeral --sandbox read-only \
  --skip-git-repo-check --json --color never -C <empty_cwd> - < <prompt_file>

claude -p --tools Skill,Read --allowedTools 'Skill,Read' \
  --permission-prompts none --no-session-persistence \
  --output-format stream-json --verbose \
  --strict-mcp-config --mcp-config '{"mcpServers":{}}' \
  --settings '{"disableAllHooks":true}' --no-chrome \
  --add-dir <home>/.claude/skills < <prompt_file>
```

Codex는 읽기 전용 sandbox를 사용했습니다. Claude Code는 `Skill`·`Read`와 사용자 Skill 디렉터리 전체를 허용하고 외부 MCP·사용자 hooks를 세션 옵션으로 제외했습니다. 특정 Skill만 허용하거나 모델·사용자 설정 파일을 변경하지 않았습니다.

프로젝트와 두 설치본의 실행 전후 SHA-256은 다음과 같습니다.

| 파일 | SHA-256 |
|---|---|
| `SKILL.md` | `667244229dedec47672f419297cd4f3c29e94d0b518ed7df8cad95229f7c6fc2` |
| `references/editing-guide.md` | `07383769007f94f036889e592aeed03206ef0400f0eac61c0a2fcb01cbf150c5` |
