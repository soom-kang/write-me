# 0.3.1 검증

`2026-10-13`에 `0.3.0` 자동 윤문에서 확인한 목록화 누락을 보완했습니다. 구조 선택을 작성 앞으로 옮기고, 한 문장에 묶인 병렬 정보의 판단 기준과 원문 기준의 간결성 예외를 명시했습니다. 완료 전에도 선택한 구조를 대조합니다. 의미 보호·산문·학술 예외와 호출 description·policy는 유지했습니다.

Codex `0.162.1`과 Claude Code `2.1.296`의 새 세션에서 각각 다섯 입력을 실행했습니다. 최초 실행에서 Claude Code가 덧붙인 인과관계를 확인한 뒤 관련 지침을 보완하고, 같은 자동 윤문 입력만 두 CLI에서 한 번씩 재실행했습니다. 총 12개 세션이며, 아래 자동 윤문 행은 최종 재검증 결과, 나머지 행은 최초 실행 결과입니다.

최초 자동 윤문은 두 CLI 모두 목록화했지만, Claude Code가 “시험 운영 중이므로”를 사용해 운영 상태와 사용자 확인 필요 사이에 원문에 없는 인과관계를 추가했습니다. 해당 출력의 의미 보존은 `FAIL`로 기록했습니다. 나란히 제시된 사실·조건을 근거 없이 인과관계로 연결하지 않는 문장을 보완한 뒤, 같은 입력의 재검증에서 해소를 확인했습니다. 최초 출력과 당시 지침도 임시 기록에 보존했습니다.

Codex는 자동 윤문과 산문 예외를 포함한 편집 실행에서 설치된 `SKILL.md` 읽기 성공과 `version: "0.3.1"`을 확인했습니다. Claude Code의 이름 없는 윤문·산문 요청에서는 `Skill(write-me)`와 해당 사용자 설치 경로의 본문 확장 event를 직접 관측했습니다. Claude Code의 명시 호출은 command 발견·정상 종료·출력으로 확인했으며, 별도 본문 확장 event는 노출되지 않았습니다. 선택 여부는 사용 선언이나 완성문의 품질로 추정하지 않았습니다.

YAML·상대 링크·Markdown, 설치 실행 지침 일치, 변경 범위와 보호 파일 대조도 `PASS`입니다. 프로젝트에서는 `SKILL.md`, `editing-guide.md`, 이 설계 문서만 변경했습니다. 두 사용자 설치 경로에는 앞의 두 실행 지침만 반영했고, 각 위치의 LICENSE·나머지 파일과 기존 네 Skill의 37개 파일은 보존했습니다. README와 기존 검증 기록도 유지했습니다. 새 검증 script·framework·dependency는 추가하지 않았습니다.

실행 옵션은 `0.3.0` 자동 선택 후속 검증과 같습니다. 요청마다 빈 임시 작업 디렉터리와 새 세션을 사용했으며 기본 모델·사용자 설정은 변경하지 않았습니다. Claude Code에는 `Skill`·`Read`만 제공했고 permission denial은 없었습니다. 입력·필터링한 event·완성 응답·지침 hash는 `<work_dir>`의 `fixtures.json`, 각 플랫폼의 `results.json`·`recheck.json`에 남겼습니다. 인증 정보나 전체 도구 출력은 기록하지 않았습니다.

위 초기 검증에서 산문·학술·간결한 문장·일반 질문은 각 한 번, 자동 윤문은 보완 전후 각 한 번 실행했습니다. 같은 최종 지침으로 수행한 후속 반복 검증은 아래에 구분합니다. Desktop 화면 확인과 전체 과거 사례 재실행은 `NOT_RUN`입니다. 이전 버전의 실패·미실행 기록은 당시 결과로 보존합니다.

## 동일 입력 3회 반복 검증

`2026-10-13`에 최종 `0.3.1`과 앞선 이름 없는 윤문 입력을 고정한 채 Codex·Claude Code에서 각각 정확히 3회 실행했습니다. CLI 버전·기본 모델·실행 옵션은 앞선 자동 선택 검증과 같으며, 실행마다 빈 임시 디렉터리와 새 세션을 사용했습니다. 6개의 서로 다른 session ID를 확인했고 입력·설치 지침의 SHA-256도 대조했습니다. 도중에 Skill·입력·설정을 바꾸거나 실패 회차를 재시도하지 않았습니다.

세 기준은 따로 평가했습니다. 자동 선택은 Codex의 설치 지침 읽기 성공 또는 Claude Code의 `Skill(write-me)`와 본문 확장 event로 확인했습니다. 불릿은 병렬 확인 항목의 실제 목록화를, 의미 보존은 기능·확인 가능 정보·시험 운영·사용자 확인 필요의 유지와 새로운 인과관계가 없는지를 검토했습니다. 세 기준이 모두 `PASS`인 실행만 전체 통과로 셌습니다.

이번 반복 검증에서는 **두 CLI 모두 세 기준을 일관되게 유지하지 못했습니다**. 선택이 관측된 네 실행은 불릿 정리와 의미 보존도 충족했습니다. 실패한 두 실행에는 공통으로 선택·읽기 기록이 없었으며, Claude Code는 세 회차 모두 발견 목록에 `write-me`가 있었습니다. 발견 가능한 상태와 실제 선택은 구분해야 합니다. 선택 누락의 내부 원인은 이번 기록만으로 확정하지 않습니다.

6회 모두 정상 종료했고 Claude Code의 permission denial은 없었습니다. 따라서 위 실패는 실행 장애인 `BLOCKED`로 분류하지 않습니다. 이 수치는 한 입력에 대한 소수의 관측 결과이며 일반적인 성공 확률이나 제품 전체의 신뢰도로 해석하지 않습니다.
