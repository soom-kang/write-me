# 0.3.2 검증

`2026-10-13`에 자동 선택 누락을 조사하고 description·호출 조건·버전만 변경했습니다. `입력과 기본값` 이후의 편집 절차는 `0.3.1`과 bytes가 같습니다. 의미 보호, 병렬 항목의 불릿, 산문·학술·간결한 원문의 예외와 본문 명령 미실행 규칙을 유지했습니다.

## 자동 선택 누락 분석

| 구분 | 확인한 사실과 판단 |
|---|---|
| `[Verified]` 이전 실패 위치 | `0.3.1` 반복 검증에서 두 CLI의 3회차는 모두 도구 호출·Skill 읽기 없이 산문으로 답했습니다. Claude Code는 그 실행에서도 command 목록에 `write-me`가 있었고 permission denial은 없었습니다. 따라서 해당 실행의 목록화 누락은 Skill을 선택한 뒤 규칙을 어긴 사례와 구분합니다. |
| `[Verified]` 현재 발견·설치 상태 | 변경 전 Codex `skills/list`에서 기존 사용자 경로의 `write-me` 한 개, `enabled: true`, description과 오류 없음이 확인됐습니다. 두 설치본의 실행 지침은 프로젝트와 같고 Codex의 자동 선택 policy는 `true`였습니다. 설치본의 기존 LICENSE 차이는 이번 문제와 관계없이 보존했습니다. |
| `[Inference]` 보완할 선택 신호 | 기존 description은 기능 범주를 설명했지만 실제 요청 표현인 ‘자연스럽게 다듬기’와 이름 없는 짧은 편집 요청을 명시하지 않았습니다. 일반 답변으로 처리하기 쉬운 요청에서도 적용 범위를 알아볼 수 있도록 이를 앞부분에 넣었습니다. |
| `[Unverified]` 정확한 내부 원인 | 모델이 해당 회차에서 선택을 생략한 이유는 event만으로 확정할 수 없습니다. 목록 발견은 매 요청에 description 전체가 전달됐다는 증거가 아닙니다. description 축약·누락, 다른 Skill과의 경쟁, 모델의 판단 변동 중 어느 것이 원인인지 분리하지 못했습니다. |

공식 문서는 이름·description으로 후보를 판단한 뒤 본문을 로드하는 구조를 설명하며, Skill이 많을 때 설명이 축약되거나 빠질 수 있음을 안내합니다. 이 동작은 가능한 원인을 설명하는 근거이며, 이번 실패에서 실제로 설명이 잘렸다는 증거는 아닙니다. 호출 조건을 본문에 추가하는 것만으로 선택을 강제할 수 없으므로 frontmatter도 함께 보완했습니다. [Codex 공식 안내](https://learn.chatgpt.com/docs/build-skills), [Claude Code 공식 안내](https://code.claude.com/docs/en/skills#skill-not-triggering)

설명에는 편집 의도와 범위 밖 요청을 함께 남겼습니다. 회의록이라는 특정 소재를 trigger로 만들지 않았으며, 산문·학술 문체는 호출 대상에서 제외하지 않고 기존 형식 보존 규칙을 적용합니다. 자동 선택 policy·도구 권한·모델 설정·참조 문서는 변경하지 않았습니다.

## 같은 이름 없는 요청을 각 3회 실행

Codex `0.162.1`과 Claude Code `2.1.296`에서 이전 반복 검증의 입력을 그대로 stdin으로 전달했습니다. Skill 이름·호출 표기·경로·불릿 지시는 넣지 않았습니다. 입력의 SHA-256은 `5a3a5a7952375a94128f23e046fddb81b8aa7aee86a473229427850c9e70d234`입니다.

각 요청은 빈 임시 작업 디렉터리와 새 최상위 세션에서 실행했습니다. 여섯 session ID가 서로 다름을 확인했고, 실행 전후 설치 지침의 SHA-256도 고정했습니다. CLI별 세 회차는 순서대로 실행했으며, 도중에 지침·입력·옵션을 바꾸거나 실패 회차를 대체하는 재시도를 하지 않았습니다. 기본 모델을 사용하고 사용자 설정 파일은 수정하지 않았습니다.

## 범위 밖 대조와 설치·구조 확인

일반 질문 `2 더하기 2는 얼마인가요? 답만 주세요.`는 별도의 새 세션에서 CLI별 한 번씩 실행했습니다. 두 CLI 모두 `4`를 반환했고 도구·Skill 호출과 Skill 읽기가 없어 `PASS`입니다. 이 두 실행은 위 3회 반복 집계에 포함하지 않습니다. 여덟 최상위 요청 모두 정상 종료했고 Claude Code의 permission denial은 없었습니다.

실행 명령은 앞선 자동 선택 검증과 같습니다. Codex는 `--no-daemon exec --ephemeral --sandbox read-only --skip-git-repo-check --json --color never -C <neutral_cwd> -`를 사용했습니다. Claude Code는 `--tools Skill,Read --allowedTools 'Skill,Read'`와 사용자 Skill 디렉터리 전체를 허용했습니다. 특정 Skill만 허용하거나 지침을 prompt에 삽입하지 않았으며, 외부 MCP와 사용자 hooks를 제외하는 기존 세션 옵션을 유지했습니다.

| 확인 항목 | 결과와 범위 |
|---|---|
| 패키지 구조 | `PASS`: 프로젝트와 두 설치본에 기존 `quick_validate.py`·cached `PyYAML` 사용 |
| 실행 계약 보존 | `PASS`: `입력과 기본값` 이후 본문은 변경 전과 bytes 일치. 의미 보호·산문·학술 예외·본문 명령 미실행·변경량 계산 유지 |
| 설치 반영 | `PASS`: `~/.codex/skills/write-me/SKILL.md`와 `~/.claude/skills/write-me/SKILL.md`만 백업 후 갱신. 두 설치 지침은 프로젝트와 일치 |
| 문서·변경 범위 | `PASS`: YAML·Markdown·상대 링크 확인. 프로젝트의 기존 9개 파일 중 `SKILL.md`와 이 설계 문서만 변경 |
| 기존 자산 | `PASS`: README·이미지·참조·설정·각 위치의 LICENSE와 기존 네 Skill의 37개 파일을 변경 전 SHA-256과 대조해 보존 확인 |

Git 저장소가 아니므로 초기·최종 파일 목록과 SHA-256, 본문 차이로 범위를 확인했습니다. 새 검증 코드 파일·script·framework·dependency는 추가하지 않았습니다. 제한된 실행 환경의 최초 app-server 발견 조회는 응답을 받지 못해 `BLOCKED`였으며, 승인된 환경에서 같은 읽기 전용 조회를 완료했습니다. 이는 위 모델 실행의 실패 회차에 포함하지 않습니다.

입력·필터링한 event·최종 응답·session ID·hash는 `<work_dir>`의 `input.json`, `discovery-before.json`, 각 CLI의 `results.json`과 `general-question/result.json`에 기록했습니다. `assessments.json`은 출력 검토, `final-checks.json`은 변경 범위 확인 결과입니다. Codex 1회차에는 `collab_tool_call` event도 관측됐으며, 반복 횟수는 최상위 요청 기준으로 집계했습니다. 인증 정보·전체 설정·일반 도구 출력은 저장하지 않았습니다. 임시 기록이 정리되어도 이 문서에서 입력·최종 출력·판정을 확인할 수 있습니다.

## 첫 반복 검증의 한계

아래 항목은 앞선 회의록 입력 검증 시점의 범위입니다. 추가로 수행한 검증은 다음 절에 구분합니다.

- `NOT_RUN`: 다른 표현·소재·모델·CLI 버전에서의 반복 검증. 이번 3회 통과는 해당 입력과 현재 환경에 한정되며 자동 선택을 보장하지 않습니다.
- `NOT_RUN`: 산문·학술 등 전체 과거 사례의 실행 재검증. 해당 지침의 원문 보존을 확인했지만, 이전 버전의 출력 검증을 이번 버전의 실행 결과로 바꾸어 기록하지 않습니다.
- `NOT_RUN`: Desktop 화면, Claude.ai·Cowork·API에서의 발견·호출. 이번 대상은 두 CLI입니다.
- `[Unverified]`: 이전 누락 회차에서 모델이 받은 description의 실제 길이와 선택 생략의 내부 원인. 설치·발견 확인과 실행 event만으로 확정할 수 없습니다.
- 범위 밖 대조는 단순 계산 한 입력뿐입니다. 비슷한 어휘를 쓰는 일반 질문이나 다른 편집 Skill과의 선택 경쟁은 검증하지 않았습니다. 호출을 확실히 지정해야 할 때는 Codex의 `$write-me` 또는 Claude Code의 `/write-me`를 사용합니다.

## 표현·소재 변형과 예외 — 후속 검증
