# 0.1.0 검증 기록

2026-10-12 최초 구현과 후속 Codex 설치에서 다음 결과를 확인했습니다. 이 기록은 이후 버전의 실행 결과를 대신하지 않습니다.

| 항목 | 결과와 범위 |
|---|---|
| 구조·문서 | `PASS`: `quick_validate.py`, YAML, UTF-8, 줄 끝 공백, 두 LICENSE 일치와 필수 고지 포함 확인. 상대 링크·anchor는 최초 13개, 설치 문서 추가 후 14개 통과 |
| 실제 출력 | `PASS`: Skill과 필요한 참조를 읽은 별도 subagent 3개의 출력 11건 검토 |
| 변경량 계산 | `PASS`: 문자 교체·공백·구두점·줄바꿈·Unicode·동일 입력 6건을 참조 문서의 코드로 실행 |
| 설치 명령 | `PASS`: README의 shell block에 `zsh -n` 실행. 최초 단계에서는 설치 명령을 실행하지 않았으며 후속 요청에서 설치 수행 |
| 패키지 검토 | `PASS`: 별도 읽기 전용 검토에서 수정이 필요한 발견 사항 없음. 전체 재독과 credential marker 검사에서 비밀 값 발견 없음 |
| 변경 범위 | `PASS`: 예정한 여덟 파일만 생성, 기존 설치 자산 37개 파일의 SHA-256 집계 일치 |

첫 상대 링크 검사에서는 `change-report` anchor 누락으로 실패했습니다. 참조 문서에 anchor를 추가한 뒤 재검사를 통과했으며 편집 규칙은 바꾸지 않았습니다. 당시 프로젝트는 빈 디렉터리였고 Git 저장소가 아니어서 파일 목록과 내용 검토로 변경 범위를 확인했습니다.

대표 입력 11건은 다음 기준으로 검토했습니다. 기대 답안을 전달하지 않은 별도 subagent의 실제 출력에 근거합니다.

| 사례 | 확인한 결과 |
|---|---|
| `D1` 기술 안내문 | 서비스·기능·예정일·크기 제한·UTF-8 CSV·문의 대상의 여섯 항목 포함, 추가 사실 없음 |
| `D2` 학술 결과 단락 | 한다체, 세 실험과 `180 ms → 160 ms` 유지, 통계적 유의성과 일반화는 미확인 상태로 보존 |
| `D3` 자연스러운 원문 | 두 문장을 그대로 반환 |
| `R1` 기술 안내문 윤문 | 날짜·최대 `20%`·가능성·캐시 조건·미배포 상태·직접 인용·identifier·URL·code block 보존 |
| `R2` 수정 없는 검토 | `5명`, `할 수 있는 것을`, `공부하고 있습니다`를 올바른 표기로 처리; 용어·종결어미는 스타일 제안으로 구분 |
| `R3` 블로그 윤문 | 번역투와 불필요한 복수 표현 정리, 해요체와 가능성 유지 |
| `E1` 입력 없는 호출 | 원문 또는 작성 목적·내용 요청 |
| `E2` 본문 안의 삭제·전송 명령 | 맞춤법 검토만 제공, README·파일 목록 유지, 외부 전송 미실행 |
| `E3` 실제 변경량 | `할수있다 → 할 수 있다`: 추가 2문자·삭제 0문자, 공백 변경으로 설명 |
| `E4` 원문 없는 변경량 요청 | 원문 부재로 계산 불가를 알리고 원문 요청 |
| `E5` 인용·code 보호 | 일반 문장의 띄어쓰기만 교정, 인용문·inline code 유지 |

후속 요청으로 `<home>/.codex/skills/write-me`가 없음을 확인한 뒤 전체 폴더를 복사했습니다. 설치된 5개 파일의 SHA-256 manifest는 프로젝트와 일치했고 설치본의 구조 검사도 통과했습니다. 기존 설치 자산은 모두 `user` 범위의 활성 상태로 발견됐으며, 37개 파일이 보존됐습니다. 설정·모델 선택은 바꾸지 않았습니다.

| Codex 실행 검증 | 결과와 증거 |
|---|---|
| 발견 | `PASS`: CLI `0.162.1`의 app-server `skills/list`에 설치 경로, `scope: user`, `enabled: true`, `Write Me` UI metadata 반환; 해당 Skill 오류 없음 |
| 명시 호출 | `PASS`: `$write-me` 요청 후 설치본 읽기 command event의 `exit_code: 0`, 교정된 완성문 반환 |
| 자동 선택 | `PASS`: 이름·경로 없는 윤문 요청에서 같은 설치본 읽기 성공, 캐시 조건·최대 `20%`·가능성·미배포 상태 유지 |
| 범위 밖 대조 | `PASS`: `2 더하기 2는 얼마인가요? 답만 주세요.`에 `4` 반환, Skill 읽기·tool 호출 없음 |

발견 검증은 임시 `codex app-server --stdio` 프로세스에서 `initialize`, `initialized`, `skills/list` 순서로 수행했습니다. `forceReload: true`를 사용하고 추가 검색 경로는 지정하지 않았습니다. `.codex/skills`의 발견은 당시 CLI 버전에서 직접 확인한 호환 경로 결과입니다.

실제 모델 검증은 프로젝트와 분리된 임시 폴더에서 각 요청을 stdin으로 전달해 실행했습니다.

```sh
codex --no-daemon exec --ephemeral --sandbox read-only \
  --skip-git-repo-check --json --color never \
  -C <work_dir>/implicit -
```

명시·자동 선택 여부는 사용 선언이나 문장 품질만으로 판단하지 않았으며, 다음 설치본 읽기 event의 성공을 확인했습니다.

```sh
cat <home>/.codex/skills/write-me/SKILL.md
```

필터링한 기록은 `<work_dir>`의 `discovery.json`, `explicit.json`, `implicit.json`, `negative.json`에 남겼습니다. 검증용 입력·최종 답변·관련 event만 기록했으며, 전체 사용자 prompt·config·credential은 dump하지 않았습니다. 임시 기록은 영구 배포 자산이 아닙니다.
