# 0.3.0 검증

최초 구현 검증일은 `2026-10-13`입니다. Codex `0.162.1`과 Claude Code `2.1.296`의 새 세션에서 각각 네 입력을 실행했습니다. 출력 검토 후 두 지침을 보완하고, 영향을 받는 서비스 안내와 간결한 문장만 각 CLI에서 한 번씩 다시 확인했습니다. 아래는 보완 후 결과이며, 학술·산문과 여섯 항목 안내는 최초 실행 결과입니다. 이전 버전의 통과 기록을 이번 검증의 근거로 사용하지 않았습니다.

| 사례 | Codex | Claude Code | 직접 확인한 결과 |
|---|---|---|---|
| 일반적인 서비스 안내 윤문 | `PASS` | `PASS` | 구조화 요청 없이 기능 설명·병렬 확인 항목·운영 조건을 분리. 자동 회의록 정리, 핵심 내용 파악, 담당자·마감일 확인, 시험 운영 상태, 사용자 확인 필요 보존 |
| 학술·산문 유지 요청 | `PASS` | `PASS` | 한다체 산문, 설명 가능성, 통계적 유의성 미확인, 조건부 직접 인용과 `sample_count=5` 보존 |
| 이미 간결한 문장 | `PASS` | `PASS` | `파일을 선택한 뒤 업로드 버튼을 누르세요.`를 제목·목록·설명 없이 그대로 반환 |
| 필수 항목 6개 안내 | `PASS` | `PASS` | CSV, UTF-8, 10 MB 이하, 첫 행의 열 이름, YYYY-MM-DD, 필수 이메일 열을 모두 유지. 시험 운영·사용자 확인 조건 보존, 새 행동·소요시간·다음 단계 추가 없음 |

최초 Claude Code 출력은 서비스의 첫 기능 설명을 목록에서 반복했고, 간결한 문장에는 수정이 필요 없다는 설명과 인용 표시를 붙였습니다. 후자는 완성문만 반환하는 기준에서 `FAIL`로 판단했습니다. 기능 설명을 목록에서 반복하지 않는 규칙과 수정이 필요 없으면 원문만 반환하는 규칙을 `SKILL.md`에 명시한 뒤, 같은 입력으로 재실행해 두 문제의 해소를 확인했습니다. 최초 결과도 임시 기록에 남겼습니다.

Codex의 보완 후 두 실행과 최초 학술·여섯 항목 실행에서는 설치된 `SKILL.md` 읽기 성공과 `version: "0.3.0"`을 직접 확인했습니다. 최초 서비스 실행에는 읽기 event가 없었으므로 이를 Skill 적재의 근거로 삼지 않았습니다. Claude Code는 모든 세션의 command 목록에서 `write-me`가 발견됐고 명시 `/write-me` 호출이 정상 종료됐습니다. 위 명시 호출에서는 별도 본문 확장 event가 노출되지 않아 본문 적재를 직접 관측한 것으로 표현하지 않습니다. 두 CLI 모두 마지막 완성 응답을 평가했으며 실행 중 진행 안내는 결과물과 구분했습니다.

이번 설치에서는 `~/.codex/skills/write-me`와 `~/.claude/skills/write-me`의 `SKILL.md`·`references/editing-guide.md`만 갱신했습니다. 프로젝트와 각 설치본의 기존 LICENSE 차이는 그대로 유지했으며 패키지 전체가 동일하다고 판단하지 않습니다. Git 저장소가 아니므로 초기·최종 파일 목록과 내용으로 변경 범위를 확인했습니다.

실행 옵션은 아래 `0.2.0` 기록의 CLI 명령과 같고, 각 입력은 프로젝트와 분리된 임시 작업 디렉터리에서 stdin으로 전달했습니다. 기본 모델과 사용자 설정 파일은 변경하지 않았습니다. Claude Code는 `Read`·`Skill`만 제공했고 permission denial은 없었습니다. 검증용 입력과 필터링한 결과는 `<work_dir>`의 `fixtures.json`, 각 플랫폼의 `results.json`·`recheck-results.json`에 저장했습니다. 기록은 임시 검증 자료이며 배포 패키지에 포함하지 않습니다.

## 자동 선택과 범위 밖 대조 — 후속 검증

`2026-10-13`에 Codex `0.162.1`과 Claude Code `2.1.296`에서 이름 없는 윤문 요청과 일반 질문을 각각 한 번 실행했습니다. 네 요청은 모두 독립된 새 세션과 빈 임시 작업 디렉터리를 사용했습니다. 입력에 Skill 이름·호출 표기·경로·사용 지시는 넣지 않았고, 프로젝트 및 설치본의 `0.3.0` 실행 지침이 일치함을 실행 전에 확인했습니다.

| 확인 항목 | Codex | Claude Code | 직접 확인한 근거 |
|---|---|---|---|
| 이름 없는 한국어 윤문에서 자동 선택 | `PASS` | `PASS` | Codex는 사용자 설치 경로의 `SKILL.md` 읽기 `exit_code: 0`과 `version: "0.3.0"`을 관측. Claude Code는 `Skill(write-me)` 호출과 해당 사용자 설치 경로의 본문 확장 event를 관측 |
| 무관한 일반 질문에서 미호출 | `PASS` | `PASS` | `2 더하기 2는 얼마인가요? 답만 주세요.`에 둘 다 `4` 반환. 도구 호출·Skill 읽기·Skill 호출 없음 |
| 자동 윤문 결과의 핵심 정보 보존 | `PASS` | `PASS` | 회의 종료 후 자동 정리, 핵심 내용 파악, 업무별 담당자·마감일 확인, 시험 운영 상태, 사용자 확인 필요 유지 |
| 자동 윤문 결과의 병렬 항목 목록화 | `FAIL` | `FAIL` | 두 출력 모두 문단을 나눴지만 담당자·마감일 등 병렬 확인 항목을 불릿으로 정리하지 않음 |

자동 선택은 사용 선언이나 글의 품질로 추정하지 않고 호출·읽기 event로 확인했습니다. 선택에 성공해도 편집 기본값을 항상 따르는 것은 아닙니다. 위의 명시 호출 검증과 달리 이번 자동 호출에서는 목록화 기준을 충족하지 못했으며, 이 결과를 별도 실패로 남깁니다. 이번 후속 작업은 실행 확인과 문서 갱신으로 한정하여 Skill·설정·설치본은 수정하지 않았습니다.

Codex는 앞서 기록한 읽기 전용 CLI 옵션을 사용했습니다. Claude Code는 자동 선택을 특정 Skill로 제한하지 않도록 `Skill`·`Read` 도구를 허용하고 사용자 Skill 디렉터리 전체를 추가했습니다. 실행 명령은 다음과 같습니다.

```sh
claude -p --tools Skill,Read --allowedTools 'Skill,Read' \
  --permission-prompts none --no-session-persistence \
  --output-format stream-json --verbose \
  --strict-mcp-config --mcp-config '{"mcpServers":{}}' \
  --settings '{"disableAllHooks":true}' --no-chrome \
  --add-dir <home>/.claude/skills
```

기본 모델과 사용자 설정 파일은 유지했습니다. Claude Code의 두 세션 모두 `write-me`가 command 목록에 있었으며 permission denial은 없었습니다. 일반 질문에서는 발견 가능한 상태에서도 호출하지 않았습니다.

입력과 필터링한 event·완성 응답은 `<work_dir>`의 `fixtures.json`, `codex/results.json`, `claude/results.json`에 저장했습니다. 전체 설정·인증 정보·일반 도구 출력은 기록하지 않았습니다. 프로젝트에서는 이 설계 문서만 변경했고, 두 설치본과 기존 네 Skill은 변경 전 SHA-256과 대조해 보존을 확인했습니다. Markdown·상대 링크·최종 파일 범위 검사도 통과했습니다. 새 검증 script·framework는 추가하지 않았습니다.

`NOT_RUN`: Desktop 화면 확인, 전체 과거 사례 재실행, 목록화 실패를 고친 뒤 재검증. CLI별 자동 선택·일반 질문 결과는 각 한 입력의 한 번 실행에 한정되며, 모든 요청·모델·제품 환경의 동일한 동작을 보장하지 않습니다.
